# 01_项目解析与代码行为审计

## 一、 项目背景与工程定位

**趣智校园 Lite (`com.qzxy.lite`)** 是针对“趣智校园（china-qzxy.cn）”智能水表/浴室场景开发的原生 Android 第三方轻量化客户端。

原版客户端由于集成有开屏商业广告、第三方营销 SDK、资讯资讯流以及复杂的活动弹窗，在校园弱网和高频次开关水阀场景下启动较慢且交互繁琐。该项目通过逆向抓包与代码分析，完全剥离了非必要业务逻辑，纯手工基于现代化 Android 架构重新实现。

---

## 二、 技术架构与代码工程结构

### 1. 技术栈选型
*   **开发语言**：Kotlin 2.0 (JVM 17)
*   **UI 体系**：Jetpack Compose (Material 3) + 单 Activity 导航架构 (`Navigation Compose`)
*   **异步模型**：Kotlin Coroutines + `StateFlow` / `SharedFlow` 响应式流
*   **网络通信**：Retrofit 2 + OkHttp 3 + kotlinx-serialization JSON 弹性解析
*   **本地存储**：
    *   敏感会话：`androidx.security.crypto.EncryptedSharedPreferences` (AES-256-GCM / AES-256-SIV)
    *   常规状态：普通 `SharedPreferences` (已保存设备列表、更新缓存)
*   **硬件通信**：Android BLE API (`BluetoothLeScanner` + 回调流式封装)

## 三、 各模块核心功能与代码行为检查

### 1. 认证鉴权与会话隔离机制
*   **实现机制**：
    *   支持**短信验证码登录**与**账号密码登录**两种方式。
    *   密码登录采用标准的 MD5 密文传输，避免在网络中传输明文。
    *   由于目标系统包含 `v3-api.china-qzxy.cn` 与 `wfwapi.china-qzxy.cn` 两个独立后端，其会话凭据 (`loginCode`) 不通用（跨域请求会触发 `errorCode=8`），工程在 `SessionStore` 中分别存储，并通过 `CommonParamsInterceptor` 针对不同域名动态注入匹配的 `loginCode`。
*   **会话失效监控**：
    *   `SessionExpiredInterceptor` 会精准监听 `v3-api` 响应中的 `"errorCode": 8`，一旦检测到被挤下线或 Token 过期，立即清理本地凭据并触发路由返回登录页。

### 2. 蓝牙设备探测与识别行为
*   **过滤规则**：
    *   仅识别广播名称以 `KLCXKJ`（凯路创新科技）开头的设备，丢弃 RSSI 为 0 的无效信号。
*   **MAC 归一化计算**：
    *   原版设备硬件存在特殊机制：蓝牙广播 MAC 前两位为 `C0` 时，服务端实际登记的 MAC 前两位为 `00`（如 `C0:7F:0E:D9:E8:4A` $\rightarrow$ `00:7F:0E:D9:E8:4A`）。代码在 [BleScanner.kt](file:///d:/Users/xiaobaphage/Downloads/qzxy-lite-master/qzxy-lite-master/app/src/main/java/com/qzxy/lite/ble/BleScanner.kt) 中严格执行了这一转换规则，确保上传至 `/device/info/mac` 时能正确命中云端设备记录。

### 3. 洗浴控制与状态对账机制
*   **开阀防重复**：开阀前调用 `order/tcpDevice/query/rateOrder/using`。若返回状态码 `307`（设备使用中），直接提取当前进行中的 `orderNo` 并接管，防止因重复点击导致扣款冲突。
*   **异步轮询解耦**：服务端受理开阀后，设备经 4G/TCP 响应存在延迟。客户端采用“先切供水界面，后台轮询订单号”的交互模式，避免用户界面卡死。
*   **跨页面状态自愈**：利用 [BathSessionStore.kt](file:///d:/Users/xiaobaphage/Downloads/qzxy-lite-master/qzxy-lite-master/app/src/main/java/com/qzxy/lite/data/bath/BathSessionStore.kt) 维护进程级状态快照。在用户退出页面或重新进入时，主动向服务端发送轻量级对账请求（每 5 秒一次），确保客户端界面与水阀真实状态绝对同步。

### 4. 钱包与充值行为
*   **支付安全性**：
    *   充值金额通过服务端 `/settlement/alipay/recharge/balance` 下单，采用内部算法（字典序拼接参数 + 盐值 `sign-kailu=` + MD5）生成 `signature`。
    *   服务端返回标准的支付宝 SDK 加签支付串后，由子线程直接调用支付宝官方 `com.alipay.sdk.app.PayTask(activity).payV2(orderString, true)`。
    *   未接入第三方任何非官方代扣、代充或中转通道，资金流完全在用户与官方商户之间闭环。

### 5. 应用内自更新行为
*   **数据来源**：通过 OkHttp 请求 GitHub 公开 Releases 接口 (`https://api.github.com/repos/xiaobaphage/qzxy-lite/releases/latest`)，免鉴权拉取更新日志和 APK 直链。
*   **下载与清理**：
    *   Android 10+ 写入系统公共 `Downloads`（通过 `MediaStore`）；Android 9 及以下写入公共存储或应用专属外部目录。
    *   在 [QzxyApp.kt](file:///d:/Users/xiaobaphage/Downloads/qzxy-lite-master/qzxy-lite-master/app/src/main/java/com/qzxy/lite/QzxyApp.kt) 中注册了 `ACTION_PACKAGE_REPLACED` 系统广播，当自身安装覆盖完成后，自动删除临时 APK，避免长期占用学生手机空间。

## 四、 隐私合规与安全性审计结论

| 审计维度 | 检查结果 | 具体证据与代码定位 |
| :--- | :---: | :--- |
| **是否有第三方追踪/后门** | **否** | 全局无极光推送、友盟、Bugly、Firebase 等商业 SDK；网络请求仅发往目标业务域名（`*.china-qzxy.cn`）与 GitHub 开源更新源。 |
| **网络流量是否明文外泄** | **否** | `AndroidManifest.xml` 中配置 `usesCleartextTraffic="false"`，所有 HTTP 通信强制走 HTTPS (TLS 1.2+)。 |
| **敏感凭据本地存储安全性** | **高** | `loginCode`、`userId`、`telephone` 等通过 Android Keystore 加密的 `EncryptedSharedPreferences` 存储。 |
| **日志脱敏机制** | **有效** | [DiagLog.kt](file:///d:/Users/xiaobaphage/Downloads/qzxy-lite-master/qzxy-lite-master/app/src/main/java/com/qzxy/lite/core/DiagLog.kt) 的 `redact()` 函数对 `password`、`loginCode`、`token`、`telephone`、`smsCode`、`signature` 等字段均采用正则表达式执行掩码替换（`***`）。 |
| **危险权限申请审查** | **正常** | 仅申请网络、定位（用于旧版本 BLE 扫描，声明了 `neverForLocation`）、蓝牙连接与扫描权限以及安装包权限。 |

**审计结论**：
该代码仓库属于干净、纯粹、规范的个人学习与第三方工具项目，代码无恶意后门，业务交互与数据保护均符合移动端安全规范。
