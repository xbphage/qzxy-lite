# 04_蓝牙 BLE 协议与数据包示例

本文档基于 `趣智校园 v6.5.27` 真实脱壳 Dex 反编译代码（`com.klcxkj.bluesdk`、`libklcxkjencry.so`）以及现场抓包日志（`btsnoop_hci_261123_225033.log`）进行 100% 字节级还原，详细解释所有广播、GATT 与通信帧的**每一个字段含义**。

---

## 一、 高校脱机水表原理与架构

高校校园内大量安装的水表为**无蜂窝网络（脱机）水表**：
- 水表本体不具备 4G/NB-IoT 模块，无法与服务端维持 TCP 长连接；
- 若直接调用远程 TCP 下单接口（`/order/tcpDevice/downRate/rateOrder`），云端在探测设备无 TCP 链路后直接返回 `errorCode: 306`（“设备不在线”）；
- 必须由**手机 App 作为蓝牙中继网关**：
  $$\text{手机} \xrightarrow{\text{BLE}} \text{水表(读参数/随机数)} \xrightarrow{\text{HTTP}} \text{云端(签发开阀密文)} \xrightarrow{\text{BLE}} \text{水表(开阀)} \dots \xrightarrow{\text{BLE}} \text{水表(关阀/账单)} \xrightarrow{\text{HTTP}} \text{云端(扣费结算)}$$

## 二、 蓝牙广播数据包字段详解 (Advertisement Data)

智能水表待机时持续广播 BLE 报文，用于手机发现设备与换取云端元数据。

### 1. 广播数据包示例 (Raw Hex)
```text
02 01 06 0B 09 4B 4C 43 58 4B 4A 5F 32 30 31 0A FF 5B 01 00 01 C0 7F 0E 3E 59 C5
```

### 2. 广播数据包字段逐项拆解说明
| 字节范围 | 长度 | 字段名称 | 原始 Hex 值 | 字段含义与解析说明 |
| :--- | :---: | :--- | :--- | :--- |
| **0x00** | 1B | `Flags Length` | `02` | Flags 结构体长度（2 字节）。 |
| **0x01** | 1B | `Flags Type` | `01` | 广播数据类型：`0x01` 代表广播标志位 (Flags)。 |
| **0x02** | 1B | `Flags Value` | `06` | 位掩码 `0x06`：Bit 1 置 1 代表通用可发现模式 (LE General Discoverable)；Bit 2 置 1 代表不支持经典蓝牙 (BR/EDR Not Supported)。 |
| **0x03** | 1B | `Name Length` | `0B` | 广播设备名称段长度（11 字节）。 |
| **0x04** | 1B | `Name Type` | `09` | 广播数据类型：`0x09` 代表完整本地设备名 (Complete Local Name)。 |
| **0x05 - 0x0E** | 10B | `Local Name` | `4B 4C 43 58 4B 4A 5F 32 30 31` | ASCII 解码为 **`KLCXKJ_201`**。前缀 `KLCXKJ` 代表凯路创新科技，后置 `201` 代表该设备所属的高校项目 ID (ProjectId=201)。客户端依赖该前缀过滤水表。 |
| **0x0F** | 1B | `Mfr Length` | `0A` | 厂商自定义数据段长度（10 字节）。 |
| **0x10** | 1B | `Mfr Type` | `FF` | 广播数据类型：`0xFF` 代表厂商自定义数据 (Manufacturer Specific Data)。 |
| **0x11 - 0x12** | 2B | `Company ID` | `5B 01` | 蓝牙 SIG 厂商标识代码（低位在前，`0x015B`）。 |
| **0x13 - 0x14** | 2B | `Device Model` | `00 01` | 内部硬件设备型号与固件版本标识代码。 |
| **0x15 - 0x1A** | 6B | `Factory MAC` | `C0 7F 0E 3E 59 C5` | 出厂硬件识别物理 MAC 地址。注：以 `C0` 开头时需归一化替换为 `00`（即 `00:7F:0E:3E:59:C5`）或以 `C4` 开头上传。 |

## 四、 串口通信帧协议结构说明 (Over-The-Air Protocol)

水表工作于透传模式，每一包传输的数据包含**外层 ASCII 封装**与**内层二进制数据帧**。

```text
外层格式：# [内层二进制字节流的 Hex 字符串] \n
```

### 内层二进制通用帧结构
```text
+--------+---------------+-----------+--------+--------+-------------+----------+--------+
| 引导头 | 长度 (Total)  | 方向标志  | 命令字 | 子命令 | 载荷 Payload| 校验和   | 结束符 |
| 1 Byte | 2 Bytes (BE)  | 1 Byte    | 1 Byte | 1 Byte | N Bytes     | 1 Byte   | 1 Byte |
+--------+---------------+-----------+--------+--------+-------------+----------+--------+
|  0x60  | payload.len+3 | 0x80/0x81 |  Cmd   |  0x00  | Data...     | Checksum |  0x16  |
+--------+---------------+-----------+--------+--------+-------------+----------+--------+
```

#### 内层通用字段含义表
| 字段名称 | 字节长度 | 取值规则与含义 |
| :--- | :---: | :--- |
| **引导头 (Header)** | 1 字节 | 固定为 `0x60`（十进制 96），用于帧同步标识。 |
| **总长度 (Length)** | 2 字节 | 大端序（Big-Endian）。数值等于：`载荷长度 + 3`（包含方向、命令字、子命令）。 |
| **方向标志 (Direction)** | 1 字节 | `0x80`：主机发往从机（手机 $\rightarrow$ 水表）；<br/>`0x81`：从机发往主机（水表 $\rightarrow$ 手机）。 |
| **命令字 (Cmd)** | 1 字节 | 标识业务操作类型：`0x23`=查询设备；`0x21`=下发开阀；`0x22`=关阀；`0x85`=采集账单；`0x86`=确认存储。 |
| **子命令 (SubCmd)** | 1 字节 | 业务子操作标识/序列号，常规通信中固定为 `0x00`。 |
| **载荷数据 (Payload)** | N 字节 | 具体业务参数、密钥密文、设备信息或账单记录。当作为响应时，第 1 个字节固定为执行状态码（`0x80` 代表成功）。 |
| **校验和 (Checksum)** | 1 字节 | 累加校验和（取低 8 位）：`Checksum = (方向 + 命令字 + 子命令 + sum(Payload)) & 0xFF`。 |
| **结束符 (End)** | 1 字节 | 固定为 `0x16`（十进制 22），标志一帧完整结束。 |

| **0x11-0x14** | 4B | `00 00 07 95` | 扣费账户 ID (AccountId) | 大端整数 `0x0795` = **1941**。 |
| **0x15-0x18** | 4B | `00 00 4D DB` | 水表设备 ID (DeviceId) | 大端整数 `0x4DDB` = **19931**。 |
| **0x19** | 1B | `02` | 扣款账户类型 (AccountType) | `0x02`：校园一卡通钱包账户。 |
| **0x1A-0x1D** | 4B | `00 00 00 02` | 账单记录序号 (RecordIndex) | 该水表内部闪存存储的第 2 条消费流水流水号。 |
| **0x1E-0x21** | 4B | `00 00 13 88` | 计费基数/单价 | 大端整数 `0x1388` = 5000（5000 厘 = 5.000 元/基准单位）。 |
| **0x22-0x25** | 4B | `00 00 00 32` | 实际出水脉冲数 (PulseCount) | 大端整数 `0x32` = **50 个脉冲**（流量传感器旋转 50 周，按 32 脉冲/升换算约为 1.56 升）。 |
| **0x26-0x29** | 4B | `00 00 00 32` | 结算计扣脉冲数 (DeductPulses)| 大端整数 `0x32` = 50 个计费脉冲。 |
| **0x2A-0x2F** | 6B | `C4 7F 0E 3E 59 C5` | 校验 MAC 地址 | 账单关联绑定的水表硬件 MAC。 |
| **0x30** | 1B | `D0` | 校验和 | 累加校验和 `0xD0`。 |
| **0x31** | 1B | `16` | 结束符 | 帧终止标识。 |

> [!TIP] 载荷数据在 HTTP 回传中的角色
> 上表中偏移 `0x06` 至 `0x2F` 共 42 字节的载荷数据转换成 Hex 字符串（`80261123225041000000c90000079500004ddb0200000002000013880000003200000032c47f0e3e59c5`），即为直接填入 HTTP `/order/upload/bluetooth/data` 的 **`xfData`** 参数！

### 5. 确认水表记录入库存储 (Cmd 0x86)

当云端扣费成功后，手机必须通知水表“该笔账单已结算”，水表收到后会将该记录标记为已确认，避免下次重复上报。

#### A. 手机下发确认入库指令 (TX)
*   外层 ASCII：`#600019808600261123225041000000c90000079500004ddb00000002a216\n`
*   内层 Hex 报文（共 30 字节）：

| :---: | :---: | :--- | :--- | :--- |

| **0x01-0x02** | 2B | `00 19` | 长度 | 25 字节（22 字节载荷 + 3 字节控制段）。 |
| **0x03** | 1B | `80` | 方向标志 | 手机 $\rightarrow$ 水表。 |
| **0x04** | 1B | `86` | 命令字 | `0x86` (十进制 134)：确认消费记录入库清除。 |
| **0x05** | 1B | `00` | 子命令 | 0x00。 |
| **0x06-0x0B** | 6B | `26 11 23 22 50 41` | 确认时间戳 | 需确认清除的记录时间：`2026-11-23 22:50:41`。 |
| **0x0C-0x0F** | 4B | `00 00 00 C9` | 项目 ID | 201。 |
| **0x10-0x13** | 4B | `00 00 07 95` | 账户 ID | 1941。 |

#### B. 水表上报确认成功响应 (RX)

| 偏移 | 长度 | Hex 值 | 字段名 | 字段含义与技术解析 |

## 六、 Native 签名机制与字段算法 (JNI Signature)

调用云端蓝牙下单接口 (`/order/downRate/bluetooth/rateOrder`) 与消费上传接口 (`/order/upload/bluetooth/data`) 时，必须携带 `signature` 参数，否则接口报错。

### 1. 签名参数字典与排序规则
- **开阀下单签名源字段**：`telephone`, `deviceId`, `xfModel`, `randomNumber`
- **消费上传签名源字段**：`loginCode`, `telephone`, `xfData`

签名必须按字段名的 ASCII 升序字典排序拼接为：
`Key1Value1Key2Value2...`

### 2. 真实签名计算实例
以开阀下单为例：
- `deviceId`: `"19931"`
- `randomNumber`: `"e1000000"`
- `telephone`: `"13800138000"`
- `xfModel`: `"0"`

排序拼接后的原始明文字符串为：
```text
deviceId19931randomNumbere1000000telephone13800138000xfModel0
```

加上官方密钥盐值：
```text
deviceId19931randomNumbere1000000telephone13800138000xfModel0&key=sign-kailu-855c74a88b8b494187c99b08b8c9a744
```

对该拼接字符串进行 32 位 MD5 摘要运算，得出最终填入请求参数的 `signature`：
```text
signature = 4f2a7b8e91c28d9a441e8880f0a2d3b4
```
